# Player-seat calibration probe

`authority_player_seat_calibration.xml` and `.lua` are default-off, read-only experimental components. Importing Lua registers no X4 events or update callback; neither file installs itself, launches X4 or authorizes a save. They require a disposable, paused game that already contains the saved two-sector references, the unchanged registry and the two new player fixture references. The caller must verify the source save and process identity, own and serialize all callback delivery, install exactly one private update owner, supply a fresh 32-hex nonce and fence the profile and owned process. The Lua guard checks its configured save path, player validity, pause and monotonic deadline at observation points; these checks do not prove uninterrupted pause or OS process identity.

The MD reader chooses slot 0 as the previously registered sector-2 NPC and slots 1/2 as the new Company ships. It checks epoch, operational ship and sector context, the registry mapping for slot 0, Company ownership and macro for fixture slots, and rejects player, docked or stored ships. It reads `controlpostslot.{controlpost.aipilot}` and requires a nonempty slot and associated component before reading `slot.component.slotactor.{slot}`. These two getter expressions are not suppressed with `@`; a script error or absent reply must be treated as an inconclusive timeout. One response includes request ID, epoch, slot, local actor, local sector and reported reservation state; runtime IDs are local to this X4 process, not portable world identities.

Lua independently validates local actor/sector handles and context, samples sector-relative coordinates and `GetComponentData(ship, 'hullpercent')`, and asks `GetComponentData(ship, 'assignedpilot')`. A thrown getter error fails; a non-nil pilot must resolve to a valid component. A nil result is recorded as `nil_observed`, not as proof that a pilot does not exist: this API can fail silently and its behavior for these fixtures is not established. Both getters must report a positive on the NPC control before the two fixture observations can complete. Even if both fixture assignments return nil and both reservation reads report empty, the result is always `classification='inconclusive'`, `seat_free_proven=false`, `player_control_proven=false`, and `save_authorized=false`. These observations cannot establish physical chair occupancy, control ownership, full hull, collision clearance, or seat usability. The save bridge remains disabled.

The fake Lua and FFI tests exercise correlation, positive control, loss of pause/deadline, invalid or missing getters, duplicate actors, sector mismatch, and callback reentrancy. They do not run X4. The XML schema check validates structure rather than MD expression meaning. A real disposable positive/negative calibration has not been performed, nor has a native slot read, save or teleport been authorized by this probe. See `AUTHORITY-PLAYER-PILOT-RESEARCH.md` for the local vanilla script references and their differing meanings.
